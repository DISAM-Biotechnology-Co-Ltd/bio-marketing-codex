# 範本：提案簡報逐頁稿

寫之前必須先讀 `references/deck-architecture.md`、`references/audience-and-delivery.md` 與 `references/visual-prompts.md`。

- 頁數 N 由 Gate 3 決定，不得自行增減。
- 觀看方式為「現場講述」→ 只產出講述版；「會後寄送閱讀」→ 只產出閱讀版；「兩者都要」→ 兩份都產出，頁序與標題完全一致。
- 所有功效宣稱只能逐字使用 approved_wording，並在有宣稱的頁面標註 claim id；痛點、情境、提案邏輯等不需宣稱的內容可以自由撰寫（見 `claim-rules.md` 第 4 節）。
- 主幹頁與附錄不放「［待補］」，標題、頁面文字、銜接句不寫自我否定句；缺資料的處理見 `deck-architecture.md` 第 7 節。
- 「幕」是規劃用語，不寫進簡報檔：標題、標題大綱、頁面文字、講者備註、銜接句都不出現「第一幕」「五幕」「本幕」，也不把幕的名稱（例如「認知破局」）當章節標籤。頁數分配表寫在內部工作稿第 1 節。

## 共用開頭（兩版都要）

```markdown
# {產品名}｜{簡報目的} 提案簡報（{講述版／閱讀版}）

- 聽眾：{Gate 3 聽眾}
- 會議長度：{分鐘}｜主幹頁數：{N}｜附錄：{有／無，幾頁}
- 本場要對方做的決定：{依簡報目的}

## 標題大綱（只看標題就能讀懂整場）
1. …

## 插圖製作設定（製作用，不要放在簡報上）
- 製作順序：先生成主視覺產品圖並確認外觀；定稿後，其他含產品的頁面把它上傳當參考圖，再貼上該頁 prompt。全部生成後對照一次，外觀跑掉就重做。
- 風格設定：{English style lock，每段 prompt 逐字使用}
- 產品外觀定義｜{產品名}｜{模擬／實際包裝}：{English，每個含產品的 prompt 逐字使用；不呈現產品外觀時省略這行}
```

## 講述版：每頁格式（03_簡報_講述版.md）

```markdown
## 第 {n} 頁｜{結論式標題，15 字內}
- 頁面文字：
  - （2–3 點，精簡）
- 建議視覺：（圖表、表格或版面安排）
- 插圖評估：需要，含產品「{產品名}」／需要，不含產品／不需要；{一句原因}
- 插圖用途：{一句繁體中文；不需要插圖時省略}
- 插圖 Prompt（製作用，不要放在簡報上）：{English，單行；不需要插圖時省略}
- 講者備註：（50–120 字，口述補充、關鍵數值與出處）
- 銜接句：（帶到下一頁的一句話；最後一頁省略）
- 宣稱來源：cl-○（沒有宣稱寫「無」）
```

講述版最後附上：

```markdown
## 行前準備清單
（照 deck-architecture.md 第 6 節，PM 自行勾選）

<!-- check:ignore-start -->
## 會前待確認清單（PM 內部用，簡報前刪除）
| 項目 | 原本要用在第幾頁 | 向誰取得 |
| --- | --- | --- |
| ［待補：○○］ | 第 ○ 頁 | 研發／業務／… |
<!-- check:ignore-end -->
```

沒有缺漏時，省略「會前待確認清單」整段。包裝狀態為實際包裝、檔案尚未提供時，把「包裝設計檔」列入這份清單。

產品外觀為模擬時，含產品插圖的頁面要在頁面文字（閱讀版為內容）標示「模擬示意圖」。

## 閱讀版：每頁格式（04_簡報_閱讀版.md）

```markdown
## 第 {n} 頁｜{與講述版相同的標題}
- 內容：（完整論述，含數值、單位、期間、比較基準、條件；講述版放在講者備註的內容寫進這裡）
- 建議視覺：（圖表、表格或版面安排）
- 插圖評估：（與講述版同頁相同）
- 插圖用途：（與講述版同頁相同）
- 插圖 Prompt（製作用，不要放在簡報上）：（與講述版同頁逐字相同）
- 來源：（PMID／DOI／URL，查核日期）
- 宣稱來源：cl-○（沒有宣稱寫「無」）
```

## 附錄抽屜（兩版相同）

```markdown
## 附錄 A{n}｜{研發／法規／供應／商業}抽屜｜{結論式標題}
- 內容：
- 來源：
```

附錄只放 PM 有提供或已查證的資料。缺的資料不要整頁憑空生成，也不寫［待補］頁；改列進講述版的「會前待確認清單」與內部稿。
