# 系列模式

只有 PM 在 Gate 0 選了「系列模式」才讀這份。單一產品流程不讀、不套用。

系列模式的原則：**證據與宣稱逐款審查，簡報才合併**。任何一款的證據都不能借給另一款用。

## 1. 產品代號與範圍

- 適用 2–8 款成品。超過 8 款時，在 Gate 0 建議 PM 拆成幾組分開跑，例如依劑型或客群分組。
- Gate 0 摘要用表格列出每款：代號、產品名、主要成分與劑量、劑型、品類。代號依序用 `p1`、`p2`…。
- 系列層級共用的內容（共同市場、共用技術平台、品牌定位）用代號 `series`。
- 各款品類不同（例如同時有保健食品與化粧品）時，每款依自己的品類套用宣稱規則；Gate 0 摘要要標出來。

## 2. Phase 1 與 Gate 1

Phase 1 改成：
1. 系列層級：提出 3 個系列定位假說（整個系列要解決什麼問題、為什麼要一起賣），以及 3 個產品目標客群。
2. 每一款：1 句在系列中的角色（例如入門款、進階款、搭配款），以及 1 個主打點。主打點必須來自這一款自己的成分與證據。不再對每款各提 4 個協同假說。
3. 資料缺口照原規則分三類，每項標明是哪一款或 `series`。

Gate 1 改成一次問三題：
- 系列定位（3 個選項＋其他）
- 產品目標客群（3 個候選＋其他）
- 資料缺口怎麼處理（選項同原流程）

每款的角色與主打點，用表格列在 Gate 1 摘要中當「採用值」，PM 可用「其他」更正。

## 3. Gate 3 頁數檢查

系列簡報主幹最少需要 4＋產品數 頁（第一＋二幕 1 頁、第三幕 1 頁、每款至少 1 頁、比較表 1 頁、第五幕 1 頁，合併後至少 4＋K）。

PM 選的頁數 N 小於 4＋產品數時，在 Gate 3 問頁數時先提醒：「{K} 款產品至少需要 {4+K} 頁」，並在選項中列出建議頁數。PM 仍堅持原頁數時，照 PM 的選擇，把放不下的產品細節移到附錄，並在頁數分配表註明。

## 4. 證據與宣稱標示（Phase 3、Phase 3.5）

- 每筆 evidence_record 加 `products` 陣列，列出這筆證據**實際適用**的產品代號。
  - 文獻研究的是 A 款的成分與劑量，就只列 A 款。
  - 多款含同一成分、且劑量在研究範圍內，才可以一起列。劑量不同時，只列劑量相符的款。
  - 共用平台或製程的公司資料，可以列出所有使用該平台的款。
  - 不得因為成分相似或同系列，就把證據列給其他款。
- 每筆 claim_record 加 `product`：單一產品代號，或 `series`。
  - 單款宣稱只能引用 `products` 含該款的證據。
  - `series` 宣稱原則上只寫平台、製程、品牌定位這類非功效說法，claim_type 標 `business`。其他 claim_type（包括 `structure_function` 這類功能性說法）都當成功效：引用的證據合起來必須涵蓋每一款，做不到就改成單款宣稱。

## 5. Gate 4 與 Gate 4.5

- Gate 4 宣稱表依產品分組：先列 `series`，再依 p1、p2… 排列。欄位在原本的基礎上加「產品」欄。表格前先列每款的宣稱數量與 allowed／rewrite_required／prohibited／internal_only 各幾條。選項與原流程相同；PM 可只針對某一款修改。
- Gate 4.5 缺口表加「產品」欄。

## 6. 產出（Phase 4）

輸出資料夾：`bio-marketing-output/<系列名>_<YYYYMMDD>/`，檔名與原流程相同，各檔內容調整如下：

| 檔案 | 系列模式結構 |
|---|---|
| 01 內部工作稿 | 第 1 節「系列總覽」（設定、系列定位、每款角色表），之後每款一節，照原範本的章節寫；補資料任務表與宣稱審查表都加「產品」欄 |
| 02 對外企劃稿 | 系列總覽在前，之後每款一節；最後一節為系列比較表 |
| 03／04 簡報 | 依第 7 節的系列五幕 |
| 05 機轉互動頁 | 同一頁：上方是共用平台機轉，下方每款一個區塊，各自說明成分與機轉 |
| 06／07 提示詞 | 在開頭說明這是系列簡報、共幾款、每款頁數，以及「每款只能使用該款核准宣稱」 |

bundle.json 加 `products` 陣列：

```json
{
  "products": [{"id": "p1", "name": "產品名"}, {"id": "p2", "name": "產品名"}],
  "evidence_records": [{"id": "ev-1", "products": ["p1"], "...": "..."}],
  "claim_records": [{"id": "cl-1", "product": "p1", "...": "..."}],
  "external_files": ["02_對外企劃稿.md"]
}
```

`check_claims.py` 看到 `products` 就會檢查跨產品引用。出現 `PRODUCT_EVIDENCE_MISMATCH` 或 `SERIES_CLAIM_EVIDENCE_GAP`，要回頭修正 claim_record 或證據標示，不得為了通過檢查而把證據的 `products` 加大。

## 7. 系列簡報五幕

| 幕 | 系列模式內容 | 頁數 |
|---|---|---|
| 一＋二 | 系列共同的市場現況與認知破局 | 至少 1 頁 |
| 三 | 共用技術平台與製程；沒有共用平台時，改寫成系列的設計邏輯 | 至少 1 頁 |
| 四 | 每款一個小節：角色、主打點、該款的證據 | 每款至少 1 頁 |
| 五 | 系列比較表（每款的角色、主打點、劑型、目標客群）1 頁，加商業條件與 CTA | 至少 2 頁 |

- N 多出的頁數，先依 `deck-architecture.md` 的聽眾加權加給第一～三幕與第五幕，再平均補給第四幕各款。
- 頁數分配表要列出第四幕每款各幾頁。
- 每頁的「宣稱來源」欄只能填該頁產品（或 `series`）的 claim id。
- 第五幕的比較表只能放各款已核准的說法，不得出現某款沒有證據支持的欄位內容；沒有的寫「—」。
- `deck-architecture.md` 第 5 節的檢核表照常適用，另加：每款至少 1 頁、比較表存在、沒有跨產品引用 claim id。
