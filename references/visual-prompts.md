# 簡報插圖與產品外觀

寫 `templates/deck-content.md` 或 `templates/deck-prompt.md` 前必讀，並搭配 `deck-architecture.md` 與 `audience-and-delivery.md`。

插圖 prompt 是製作用的文字，給 PM 貼到生圖工具。Prompt 本身不是簡報內容，不得放上投影片。

## 1. 哪些頁面需要插圖

先看頁面類型：

| 頁面類型 | 判斷 | 視覺做法 |
|---|---|---|
| 封面、痛點與情境、產品或使用情境、感官體驗、CTA | 通常需要 | 插圖 |
| 數據與研究結果、法規與宣稱詞庫、規格與商務條件、比較表 | 通常不需要 | 用「建議視覺」描述圖表或表格 |
| 機轉與技術 | 視聽眾而定 | 研發聽眾用科學圖解；其他聽眾可用概念示意插圖 |
| 附錄 | 不做插圖 | 表格或圖表 |

再依這場簡報的情境調整：

| 情境 | 調整 |
|---|---|
| 聽眾是品牌 PM、通路、高層 | 情境與產品頁多用插圖，幫助記憶與想像 |
| 聽眾是研發、採購 | 減少裝飾性插圖，寧可用圖表、表格 |
| 多聽眾 | 依主幹的共同關切判斷，不為單一角色加圖 |
| 現場講述 | 頁面文字少，插圖可以是頁面主體 |
| 會後閱讀 | 圖文並重，插圖不得佔掉放完整條件與數值的空間 |
| 兩者都要 | 兩版同一頁用同一張圖、同一段 prompt |

每張圖都要有用途，說得出它幫這一頁傳達什麼。說不出來就判「不需要」，不要為了版面好看而配圖。

## 2. 圖片也算宣稱

Prompt 與生成的圖片都受 `claim-rules.md` 約束。不得出現：

- 使用前後對比、皮膚或身體變好的畫面，以及任何暗示效果的視覺
- 醫療或疾病意象：病患、傷口、白袍背書、手術與診療場景
- 虛構的認證標章、獎項、檢測報告、專利文件
- 真實品牌、競品包裝與名人；也不要用「像某品牌」來描述風格
- 把細胞或動物研究畫成人體效果；機轉圖只能是概念示意

圖表與數據不用 AI 生成，一律放在「建議視覺」，用實際數值製作。

## 3. Prompt 的寫法

- Prompt 用英文，單行。「插圖用途」用一句繁體中文，讓 PM 判斷這張圖要做什麼。
- 每段 prompt 都逐字包含「風格設定」，並寫明畫面主體、構圖、光線與比例（投影片通常為 16:9）。
- 除了第 4 節的實際包裝之外，每段 prompt 都要求圖中沒有文字與 logo（`no text, no letters, no logo`）。品名與標語之後在簡報軟體疊上：AI 生成的中文常會變形，也可能長出未經審查的宣稱。

## 4. 包裝狀態與產品外觀定義

依 Gate 3 第 5 題：

| 包裝狀態 | 產品外觀定義 | 額外要求 |
|---|---|---|
| 實際包裝（已有設計） | `Use the attached packaging file as the only product reference; keep its shape, colors, proportions and label exactly as supplied, and do not add any other text.` | 素材已附檔案時，改寫成看得到的實際外觀，並保留這句。尚未提供時，把「包裝設計檔」列入會前待確認清單與內部稿。提醒 PM：優先把檔案直接合成進情境圖，比重新生成更準確 |
| 模擬（尚無設計） | 依 PM 回答的定位寫出：容器形式與比例、材質與表面處理、瓶蓋或封口、主色與輔色、標籤區塊（空白、無文字） | 有含產品插圖的頁面，頁面文字要標示「模擬示意圖」，避免客戶以為包裝已定案 |
| 不呈現 | 不寫 | 插圖不畫成品，改用原料、應用情境或概念意象 |

### 模擬產品的定位追問（Gate 3）

素材與先前回答已有的項目不重問，列為採用值：

1. 品牌定位與價位帶：依 Gate 1 的目標客群，提出 3 個方向讓 PM 選（例如開架日常、專櫃質感、專業護膚通路）
2. 容器與規格：從素材帶入劑型與容量，沒有才問
3. 想傳達的感覺與主色

PM 答不出來時，用第 1 題所選方向的建議值，不要反覆追問。定位摘要與外觀定義列在 Gate 4 摘要，PM 可以更正。外觀定義不得寫進素材沒有的規格，也不得暗示認證或效果。

## 5. 外觀一致

- 外觀定義只決定一次，寫在「插圖製作設定」。每個含產品的 prompt 都逐字貼上，一個字都不改。
- 同一款產品的外觀定義，在講述版、閱讀版與簡報提示詞中完全相同。
- `check_claims.py` 只能檢查文字一致，看不到圖。文字 prompt 無法保證每張圖完全相同，所以「製作順序」要寫給 PM：
  1. 先生成主視覺產品圖，確認外觀。
  2. 定稿後，其他含產品的頁面把這張圖上傳當參考圖，再貼 prompt。
  3. 全部生成後對照一次；外觀跑掉的圖要重做，或直接把主視覺合成進去。
